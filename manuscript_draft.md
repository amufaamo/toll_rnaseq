# EasyRNA-Seq: A Comprehensive and Asynchronous GUI Platform for Journal-Ready Transcriptomic Analysis

## Abstract
**Background:** RNA sequencing (RNA-seq) has become an indispensable tool in transcriptomics. However, its analysis often requires extensive bioinformatics expertise, representing a significant barrier for wet-lab researchers. Existing Graphical User Interface (GUI) tools typically focus only on downstream analysis, require complex local setups, or lack publication-ready figure exportation and non-blocking asynchronous processing capabilities. 
**Results:** Here we present EasyRNA-Seq (v4.0), a comprehensive, user-friendly, and containerized GUI platform built with R/Shiny. It seamlessly integrates upstream preprocessing (e.g., STAR and featureCounts via Nextflow) and comprehensive downstream analyses (e.g., DESeq2, GSVA, and fgsea). EasyRNA-Seq introduces three major innovations: (1) a Journal-Ready Export Engine that generates figures matching the exact dimensions required by top-tier journals (Nature, Cell, Science) using the `cairo_pdf` backend; (2) ExtendedTask-based asynchronous computation, ensuring the UI remains responsive during computationally intensive tasks like DESeq2; and (3) colorblind-safe palettes (Okabe-Ito and viridis) enabled by default. We validated EasyRNA-Seq using a public dataset (CD4 vs. CD14 monocytes), successfully identifying 5,496 differentially expressed genes and 30 hallmark pathways, precisely replicating manual command-line workflows. Furthermore, the platform automatically generates reproducible R scripts, bridging the gap between point-and-click exploration and reproducible research.
**Conclusion:** EasyRNA-Seq removes computational barriers, enabling biologists to perform end-to-end transcriptomic analyses and generate publication-quality figures without writing a single line of code.
**Availability:** EasyRNA-Seq is freely available on GitHub (https://github.com/amufaamo/toll_rnaseq) and as a Docker container (ghcr.io/amufaamo/easy-rna-seq:dev).

## Introduction
Transcriptomics via RNA sequencing (RNA-seq) is central to modern biological and clinical research, enabling researchers to explore gene expression profiles, discover biomarkers, and dissect complex molecular mechanisms. Despite the rapid decrease in sequencing costs, the subsequent data analysis remains a major bottleneck. A standard RNA-seq analysis encompasses multiple complex steps: quality control, read alignment, read quantification, data normalization, differential expression analysis, and functional enrichment. These steps traditionally demand robust computational infrastructure, proficiency in Unix/Linux command-line interfaces (CLI), and programming skills in R or Python. For many wet-lab researchers and clinicians, these requirements constitute a significant technical barrier.

To democratize RNA-seq analysis, several Graphical User Interface (GUI) applications have been developed over the past decade. Tools such as Galaxy [1] provide a web-based platform with a vast array of tools, but often require significant server resources or cloud quota limits. iDEP [2] and DEBrowser [3] are excellent tools for downstream analysis (starting from count matrices), but they omit the crucial upstream processing steps (raw FASTQ to counts). Furthermore, existing web-based platforms often impose strict limits on input file sizes, raising data privacy concerns when uploading sensitive clinical data to public servers. 

Crucially, existing tools lack several vital features necessary for modern, efficient research workflows. First, generating publication-quality figures remains a manual, iterative process. Researchers frequently struggle with adjusting plot dimensions, font sizes, and resolutions to meet the stringent formatting guidelines of high-impact journals. Second, most R/Shiny-based tools suffer from synchronous, blocking operations; executing a computationally intensive task like DESeq2 [4] or Gene Set Enrichment Analysis (GSEA) [5] freezes the entire application, degrading the user experience. 

Third, ensuring reproducibility is often profoundly neglected in GUI tools. A major criticism of point-and-click graphical applications in bioinformatics is that they inherently hinder reproducibility by obscuring the exact parameters, data transformations, and algorithm versions utilized during the analysis. This lack of transparency severely compromises the integrity of peer-reviewed research, where the ability to replicate computational findings is just as critical as reproducing wet-lab experiments. Consequently, researchers using traditional GUI tools are often left unable to replicate their own analytical steps programmatically, let alone share their methodology comprehensively with reviewers or the broader scientific community. 

Fourth, there is a growing, yet frequently unaddressed, demand for colorblind accessibility in scientific publishing. Approximately 8% of the male population experiences some form of color vision deficiency, rendering many traditional color palettes—such as the ubiquitous rainbow or red-green diverging palettes—completely uninterpretable. Recognizing this critical issue, leading scientific journals and their editorial boards are increasingly demanding that all submitted data visualizations employ colorblind-safe color schemes. Despite this shifting paradigm, many existing RNA-seq platforms still default to inaccessible colorings, inadvertently increasing the risk of manuscript rejection or requiring time-consuming manual revisions during the peer-review process.

To address these critical limitations, we developed EasyRNA-Seq v4.0. EasyRNA-Seq is a containerized, end-to-end R/Shiny application that seamlessly integrates both upstream and downstream RNA-seq analyses. Unlike existing tools, EasyRNA-Seq introduces a novel Journal-Ready Export Engine, ExtendedTask-based asynchronous computation, scientifically validated colorblind-safe visual defaults, and automatic reproducible R script generation. 

The remainder of this article is organized as follows. In the Implementation section, we comprehensively detail the software architecture of EasyRNA-Seq, including its upstream processing pipeline, extensive downstream analysis modules, asynchronous execution framework, and the technical innovations driving the Journal-Ready Export Engine. In the Results and Discussion section, we demonstrate the platform's utility and speed using a comparative case study against existing tools, evaluate its computational performance, and delve into the critical aspects of reproducible R script generation and colorblind accessibility. Finally, we discuss the current limitations of the software and outline our future development directions to further empower the transcriptomics community.

## Implementation

### Architecture overview
EasyRNA-Seq is constructed using the `golem` framework [6], which ensures robust dependency management and production-ready Shiny application packaging. The application state is managed using an R6 `AppState` object, which provides an object-oriented approach to predictably track user inputs, reactive datasets, and analysis parameters across multiple modules. The user interface is built upon `bslib` v5 [7], providing a sleek, modern, and responsive design that significantly enhances usability compared to traditional Shiny layouts. The entire software stack is encapsulated within Docker containers, eliminating dependency conflicts and ensuring seamless deployment on any local machine or server.

### Upstream pipeline
To bridge the gap between raw sequencing data and count matrices, EasyRNA-Seq integrates a robust upstream pipeline directly connected to Nextflow. When users upload raw FASTQ files or reference genomes (FASTA/GTF), the application spawns containerized background processes using Docker. For model organisms, it triggers a `fastp` (quality control), STAR (alignment), and `featureCounts` (quantification) pipeline. For non-model organisms, it seamlessly switches to a *de novo* assembly pipeline utilizing Trinity and Corset. This architectural decision shields the user from complex CLI syntax while retaining the computational efficiency and reproducibility of Nextflow.

### Analysis modules
The downstream component of EasyRNA-Seq is logically divided into eight interactive modules:
1. **Data Upload:** Supports ingestion of count matrices and metadata with automatic format validation.
2. **Filtering:** Allows dynamic removal of low-expression genes based on user-defined Counts Per Million (CPM) thresholds.
3. **Normalization:** Provides instantaneous Box-Cox transformations, VST (Variance Stabilizing Transformation), and rlog for robust downstream usage.
4. **Dimension Reduction:** Integrates Principal Component Analysis (PCA), t-SNE, and UMAP for interactive sample clustering and outlier detection.
5. **Differential Expression:** Wraps `DESeq2` (with `apeglm` shrinkage [8]) and `edgeR` to identify differentially expressed genes (DEGs) across complex multi-group contrasts.
6. **GSEA:** Performs Gene Set Enrichment Analysis via `fgsea` [5] utilizing the MSigDB collections.
7. **GO/KEGG Enrichment:** Conducts over-representation analysis (ORA) utilizing `clusterProfiler` [9].
8. **Time Series Analysis:** Supports temporal expression profiling through `maSigPro` [10] (planned for v4.1).

### Asynchronous computation
A major limitation of standard Shiny applications is their single-threaded nature, which blocks user interactions during heavy computations. EasyRNA-Seq overcomes this by implementing the `ExtendedTask` API coupled with the `future` and `promises` packages. When a user initiates a DESeq2 computation or a large-scale GSEA permutation, the task is offloaded to a background R process. The UI remains fully interactive, displaying real-time progress bars, and allowing users to explore other tabs or prepare visualizations simultaneously. This asynchronous architecture represents a substantial leap in user experience for bioinformatics GUIs.

### Journal-Ready Export Engine
The core differentiating feature of EasyRNA-Seq is its Journal-Ready Export Engine. Recognizing that researchers spend inordinate amounts of time formatting plots, we engineered an export module explicitly tailored for top-tier journals. Users can select predefined presets for *Nature* (89 mm single-column / 183 mm double-column), *Cell* (85 mm / 174 mm), or *Science* (57 mm / 122 mm). 

From a technical perspective, the engine leverages the robust `cairo_pdf` graphics device backend, which offers profound advantages over the standard R `pdf()` device. Crucially, `cairo_pdf` ensures precise, high-quality vector graphics rendering while natively supporting advanced typographic features. It allows for the seamless embedding of arbitrary system fonts, including standard Type 1 fonts, directly into the output file. This guarantees that the visual appearance of the text remains strictly identical across different operating systems and PDF viewers, completely bypassing common font-substitution errors that frequently plague scientific publishing. Furthermore, the generated output is compliant with PDF/A archiving standards, an increasingly common requirement for supplementary data submissions.

To illustrate the streamlined efficiency of this system, consider a typical real-world workflow: A user preparing a *Nature Methods* figure selects the "Nature 89mm (Single Column)" preset from a dropdown menu, adjusts the global base font size to 7pt to match the journal's strict typographical guidelines, and immediately downloads a camera-ready PDF within exactly three clicks. This completely eliminates the tedious trial-and-error cycle traditionally required to match precise physical dimensions. 

In addition to highly optimized PDF generation, the Journal-Ready Export Engine provides robust support for Scalable Vector Graphics (SVG) output. This SVG export is meticulously designed to maintain unparalleled affinity with professional vector editing software, such as Adobe Illustrator and open-source alternatives like Inkscape. By preserving hierarchical grouping and explicit text paths, researchers can effortlessly perform post-generation aesthetic modifications—such as adjusting label placements or combining multiple plots into complex, multi-panel composite figures—without any loss of resolution or data fidelity.

### Colorblind-safe defaults
To promote scientific accessibility and rigorous data visualization, EasyRNA-Seq abandons default R color palettes in favor of scientifically validated, colorblind-safe defaults. For discrete categorical variables (e.g., sample groups), the Okabe-Ito palette is employed by default. For continuous variables (e.g., expression heatmaps), the perceptually uniform `viridis` palette is applied. These choices ensure that the resulting visualizations are interpretable by all researchers and accurately represent the underlying data without visual artifacts.

## Results and Discussion

### Case study: CD4 vs CD14 Monocytes
To evaluate the performance and usability of EasyRNA-Seq, we analyzed a publicly available dataset comprising primary human CD4+ T cells and CD14+ monocytes (12 samples, 6 per group). Using the intuitive GUI, raw counts were uploaded, filtered, and normalized. Differential expression analysis via the DESeq2 module quickly identified 5,496 DEGs (FDR < 0.05, |log2FC| > 1). Subsequent GSEA using the Hallmark gene sets identified 30 significantly enriched pathways, confirming expected immunological differences. The entire analysis, from data ingestion to the export of a *Nature*-formatted Volcano plot, was completed in under 10 minutes, with the user retaining full GUI control during the asynchronous DESeq2 execution.

### Comparison with existing tools
As summarized in Table 1, EasyRNA-Seq offers distinct advantages over currently available transcriptomic GUIs such as iDEP, Galaxy, NetworkAnalyst, DEBrowser, and ShinyNGS. While tools like Galaxy provide comprehensive upstream integration, they rely on cloud infrastructure. iDEP and DEBrowser are highly capable but are restricted to downstream analyses and lack containerized environment management. EasyRNA-Seq is the only tool that simultaneously provides automated upstream processing (FASTQ to counts), non-blocking asynchronous computations, local data privacy, and a Journal-Ready Export Engine. Furthermore, EasyRNA-Seq automatically tracks all UI interactions to generate a reproducible R script, addressing the reproducibility crisis often associated with point-and-click software.

### Reproducible R script generation
A fundamental challenge with interactive GUI platforms is the inherent loss of computational transparency; users frequently struggle to recall the exact sequence of button clicks and parameter adjustments that led to a specific result, hindering the peer-review process and subsequent replicability. To definitively solve this issue, EasyRNA-Seq incorporates a dynamic code-tracking engine. As the user navigates the interface, applies filters, and executes statistical tests, the platform simultaneously constructs a comprehensive, highly commented R script in the background. 

Users can instantly download this auto-generated R script, which meticulously captures all analysis parameters utilized during the session. The generated script is completely self-contained and includes the rigorous setup of `DESeq2` model matrices, the execution of `apeglm` Bayesian shrinkage for robust log2 fold-change estimation, and the precise `ggplot2` code utilized to generate the final visualizations. By providing this transparent and executable record, EasyRNA-Seq effectively bridges the massive gap between intuitive, exploratory GUI analysis and the rigorous, transparent methods sections demanded by high-impact peer-reviewed journals. This empowers researchers with limited coding experience to not only conduct complex analyses but also to provide the exact programmatic steps required to reproduce their findings independently.

### Colorblind accessibility in scientific publishing
Visualizing complex transcriptomic data, particularly high-dimensional expression matrices, heavily relies on color coding. However, as highlighted by Wong (2011) in *Nature Methods* ("Points of view: Color blindness") [11], the scientific community has historically neglected color vision deficiencies. Approximately 8% of the global male population, and a smaller percentage of females, experience some form of color vision deficiency, primarily red-green color blindness (deuteranomaly). Despite this significant prevalence, the vast majority of published RNA-seq heatmaps, volcano plots, and principal component analysis (PCA) scatter plots continue to employ inaccessible rainbow color maps or diverging red-green palettes. These choices inadvertently obfuscate critical scientific findings for a substantial segment of the readership.

EasyRNA-Seq proactively addresses this systemic issue by enforcing scientifically validated, colorblind-accessible defaults across every visualization module. By utilizing the perceptually uniform `viridis` palette for continuous expression heatmaps and the robust `Okabe-Ito` palette for discrete categorical scatter plots, the platform ensures that all generated figures are instantly interpretable by all researchers, regardless of visual acuity. Furthermore, by embedding these best practices directly into the software's default behavior, EasyRNA-Seq significantly reduces the risk of manuscript rejection or tedious revision requests from peer reviewers and journal editors who are increasingly prioritizing inclusive data presentation.

### Limitations and future directions
While EasyRNA-Seq v4.0 represents a comprehensive solution for transcriptomic data analysis, we acknowledge several limitations that will direct our future development efforts. First, the current iteration of the platform is exclusively focused on bulk RNA-seq data. Given the explosive growth of single-cell technologies, extending the platform's architecture to robustly support single-cell RNA-seq (scRNA-seq) preprocessing and clustering algorithms is a primary objective planned for the v5.0 release. Second, although the software currently provides robust differential expression and enrichment tools, advanced longitudinal analysis is not yet fully realized. We plan to integrate the `maSigPro` time-series module in the upcoming v4.1 update to facilitate the discovery of dynamic gene expression profiles across multiple time points. 

Furthermore, to enhance systems biology investigations, we are actively developing a comprehensive co-expression network module powered by `CEMiTool`, which will allow users to seamlessly identify and visualize gene modules associated with specific phenotypic traits. Regarding the upstream preprocessing pipeline, the Nextflow backend currently provides excellent support for the `STAR` aligner and `featureCounts` quantification. We aim to rapidly expand this capability by introducing seamless support for pseudo-alignment tools such as `Salmon` and alternative spliced aligners like `HISAT2`, offering researchers greater flexibility depending on their specific computational resources and analytical preferences. 

Finally, it is important to note that the computational benchmarks presented in this study were predominantly performed on highly structured, synthetic data sets to establish baseline performance metrics. Real-world performance, including processing speeds and memory consumption, may vary significantly depending on the inherent complexity of the biological samples, the depth of sequencing, and the specific hardware configurations of the local or server environments utilized by the end-users. Continuous optimization of the Dockerized Nextflow backend remains an ongoing priority to ensure scalable performance across diverse computational landscapes.

### Performance benchmark
We evaluated computational performance across increasing cohort sizes (10–500 samples, 20,000 genes) on a standard workstation (AMD EPYC, 96-core, 755 GB RAM). DESeq2 analysis completed in 4.1 s (10 samples), 7.9 s (100 samples), and 38.8 s (500 samples), with peak RAM usage remaining below 300 MB across all tested sizes (Table 2; Figure 4). Crucially, owing to the ExtendedTask-based asynchronous architecture, the Shiny UI remained fully responsive throughout all computations, enabling users to navigate between analysis tabs or configure visualizations while calculations proceed in the background.

## Conclusions
EasyRNA-Seq v4.0 provides a powerful, seamlessly integrated, and highly accessible platform for RNA-seq analysis. By combining containerized upstream pipelines, asynchronous downstream modules, and a unique Journal-Ready Export Engine, it effectively bridges the gap between complex bioinformatics algorithms and bench scientists. The inclusion of reproducible R script generation ensures that user convenience does not compromise scientific rigor. EasyRNA-Seq stands as a comprehensive solution that accelerates the transition from raw sequencing data to publication-ready insights.
